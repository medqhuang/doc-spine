# 第一作者卷宗编写标准

> **这份文件是什么**：一套**项目无关**的《第一作者卷宗》（first-author dossier）编写宪章，与《科研项目教学讲义编写标准》（`TUTORIAL_WRITING_STANDARD.md`）配对使用，构成项目的**作者层**：讲义让人"懂物理"，卷宗让人"敢署名"。卷宗要恢复的是执行 agent 内部推理时存在、但从未落盘的三样能力——**知道这个研究为什么做、知道每条结论为什么成立、掌握到能脱稿重构论证并预测变体**。文中括注的实例（Redfield 小系统检验、ε∝M、LCALCEPS 反转等）取自各项目审计实录，只作实例；剥掉实例，条款适用于任何"AI 协同推进、负责人事后接管"的科研项目。
>
> **怎么用**：讲义交付后启动卷宗（无讲义的项目先补讲义）。把本文件整份拷进项目 `docs/`；卷宗成文放 `docs/FIRST_AUTHOR_DOSSIER.md`，**单文件**（多论文项目见 §15）。卷宗未过 §13 质检不算交付；接管门分档（§11.4）——红档不投稿，黄档未过脱稿检验不谈投稿。
>
> **核心一句话**：第一作者的责任不是重走一遍执行，而是**恢复故事、理解论证、核验"核验体系"本身、沿途亲验、并脱稿重构出属于自己的版本**。卷宗就是把这五件事所需的最小材料，从工程制品（事件日志、任务报告、数字账本）翻译回物理散文，并按"故事 → 结论"重新索引。
>
> **一条设计哲学**（贯穿全文）：外部攻击不可穷举，预判-应答式的防御永远是表面功夫；但**自身的承重假设、近似、未验证锚可以穷举**。所以卷宗不做审稿人模拟、不预置问答剧本——它把力气花在两处：**把自身薄弱点穷举到完备**（§3），**把理解检验到生成性**（§7 脱稿检验）。理解透了，任何方向的提问都能现场重构出答案；防住只是理解的副产品。

---

## 0. 三条总纲（其余条款都是它们的展开）

1. **故事进门，claim 落地**——项目脊柱文档以任务（T1、T2…）为索引，论文以结论为索引，而作者的头脑以**物理故事**为索引。卷宗开篇必须先恢复故事（§0 物理故事地图），主体再按 claim 组织；任务号只作指针出现，不作叙事主语。执行的完备性另有保证：**task 是对账的单位，不是掌握的单位**——"做过的每件事都被检视"由 §6 的 task 覆盖扫描机器兑现，不由人的通读兑现。
2. **证据分级显式，绝不洗白**——每条结论挂四态标签之一：**已证 / 决策（约定） / 待验证 / 已否**；已证还要注明复核方式。把决策写成已证、把单谱系自审写成"已验证"、把事后发现倒叙成事前设计，都是卷宗的一票否决项。
3. **薄弱点穷举，撤回条件常设**——卷宗存在的理由，就是写下讲义按其宪章不能写、执行 agent 倾向于淡化的东西，并且**写全**：散在各 claim 的薄弱点必须汇入全局总表（§3），每条 claim 必须回答"**什么新证据出现，我应当撤回或降级这条结论**"。第一作者的可信不在于永远正确，而在于对自己在哪些条件下是错的了如指掌。**一份没有软肋、没有撤回条件的卷宗是失败的卷宗。**

## 1. 定位与读者契约

**读者**：已通读本项目讲义的人——物理图像和大框架已具备，但对执行细节、证据状况、决策史一无所知，且需要在有限时间内达到"能对每条结论负责、能决定投稿"的状态。

**与相邻文档的分工**（卷宗不越界）：

| 文档 | 回答什么 | 卷宗如何对接 |
|---|---|---|
| 讲义 | 这个项目是什么（学习者视角，自下而上） | 卷宗不重讲物理；需要背景时一句话 + `→ 讲义 §x` |
| claims ledger / T-reports | 数字本身、原始证据 | 卷宗引用不复制；每个数字一跳指针可达 |
| STATE.md | 事件与决策的时间线 | 卷宗把承重事件翻译成物理叙事，日期与指针保留 |
| ROADMAP | 红线、决策点、路线 | 卷宗 §1 摘投稿相关的判据，其余留指针 |

**卷宗内部的两个海拔**：§0 物理故事地图是**作者叙事**（自上而下、答辩口吻、第一人称负责），主体 §2 起是**签字责任**（逐条对证）。地图与讲义 README 的中心结论段允许内容重叠，但视角必须不同：讲义那段写给第一次读的学生扫加粗句，地图写的是"如果评委现在打断我，我怎么把这个工作讲成一个成立的故事"。地图同样不重讲推导，句末挂讲义章节指针。

**保持讲义纯净**：本标准新增的一切（薄弱点总表、翻案、投稿状态、接管检验）都住在卷宗里，**不得回灌讲义**——讲义的学习路径纯净性是它最大的资产。

**薄的纪律**：散文层（卷宗 §0–§5）目标 ≤ 1.2 万字 / 约 18 页；其中地图 ≤ 4 页、每条 claim ≤ 1 页。超了说明在重讲物理（该回讲义）或在堆细节（该留账本），回炉。

## 2. 文档骨架（八节，顺序固定）

```
§0 物理故事地图      —— 作者海拔的叙事：问题→洞见→机制→三个结论
§1 现状一页          —— 稿件/路线/时效/未闭合的门/最高危三条/接管状态
§2 逐 claim 卷宗     —— 主体：每条承重结论一节，五段式；弱 claim 带亲验步骤
§3 薄弱点总表        —— 自身假设/近似/未验证锚的全局穷举，投稿决策的直接输入
§4 方法与数据可信度  —— 流水线、验证门、事故簿、复核覆盖表
§5 路线史与失败分支  —— 寻找的故事：探索树 + 死路线的动机、死因、遗产
§6 对账差异报告      —— 机器生成，四类扫描 + 档位判定，只报差异
§7 接管清单          —— 机器生成骨架：亲验汇总、档位、脱稿检验规格与状态
```

§0–§5 是相对稳定的散文/表格层；§6–§7 是操作层（§6 每次投稿决策前重新生成，§7 随亲验与脱稿检验进度更新）。

## 3. §0 物理故事地图

**原则**：补回执行过程中消失的物理思考。agent 落盘的是事件、计划、证据、检查结果——相当于 commit history + 实验记录 + QC 报告；缺的是论文 Introduction/Discussion 那一层"为什么"。地图就是这一层，**2–4 页，必须最先读**。

**五个必答段落**：

1. **科学问题**：我们真正在问什么现象？此前为什么不知道答案？重要在哪里？
2. **此前的理解与它为何不够**：领域的朴素预期是什么（"通常认为 A → B"），它在哪里失效或未被检验。
3. **核心洞见**：一句话说出反转（"不是 X，而是 Y"），以及**为什么这不是显然的**——惊讶点是故事的发动机（实例：耦合明明在增强，冷却却变慢——因为守恒的耦合权重只能被重分配，谱稀释压过了集中）。
4. **机制链一图**：`物理输入 → 机制 → 可观测量 → claim` 的单张示意图，每个箭头对应讲义哪一章、每个 claim 对应卷宗 §2 哪一条。这张图是全卷宗的导航器，按讲义配图标准制作并渲染亲验。
5. **三句话电梯答案**：如果只许说三句"这个工作发现了什么"，就是哪三句。不是 claim 清单的复述，是排了优先级的作者答案。

**纪律**：地图过遮数检验（它天然不该有数字）；不引入讲义没教过的术语；每段句末挂讲义章节指针。**检验**：把地图单独抽出来给一个只读过讲义的人，他应能复述"问题—反转—机制—证据在哪"，并说出答辩开场三分钟。

## 4. §1 现状一页

**原则**：拍板"现在能不能投"所需的全部**事实**压进一页，每条带日期和指针。不写愿景，不写物理。

**必含条目**：
- **权威稿指认**：当前哪个文件是论文权威稿、什么阶段（markdown 一稿 / 已 RevTeX / 已润色），工程收尾清单在哪（指针到 paper README，不复制清单）。
- **投稿路线及其演化**：目标期刊、降级/升级史一行一变，**写原因**（实例：PRL 主攻 → PRR 直投 + strong-PRB floor，因 glassy 钩子被证伪）。
- **时效红线**：竞争格局、优先权窗口、"竞品做出 X 则新颖性作废"类条款（实例：三方赛跑任一家加杂质顶点则方法新颖性作废）。
- **未闭合的门**：仍在飞的验证门/任务及其对投稿的阻塞关系（实例：13.2° 第二角 θ-标度终判未闭合，GG1 压着）。
- **最高危未闭合三条**：从 §3 薄弱点总表摘"毙稿级 × 待补/待核"前三条 + 各自当前状态，一行一条。
- **接管状态**：档位（绿/黄/红，机器判定 → §11.1）+ 亲验清单完成度 + 脱稿检验状态（未启动 / 对账中 / 已通过，附对账单指针）。
- **卷宗自身的时效**：`last_synced` 日期 + 同步到 STATE 哪一行。

## 5. §2 逐 claim 卷宗（主体）

**claim 清单的来源**：有论文稿的项目，从权威稿的摘要+结论逐条提取，与 claims ledger 对齐后锁定；无论文稿的项目见 §15。承重 claim 一般 5–10 条；超过 12 条说明混入了非承重项，合并或降级到 §4。

每条 claim 固定五段式：

### 5.1 结论陈述与证据等级

原文口径一句话（与论文措辞一致，不转述），随后挂标签：

- **[已证 · 独立复核]**：有项目外谱系的复核记录（codex review、外部合作者、交叉工具）。
- **[已证 · 单一验证]**：证据充分但复核只有同谱系自审。**这不是贬义，是事实态**——但要写出来（实例：两条不可行性定理 + 格点敲除构造，全项目 grep 无任何独立复核记录，讲义却以定论语气呈现）。
- **[决策 / 约定]**：不是被证明的，是被选定的（单位制、系综约定、口径选择）。
- **[待验证]**：论文依赖但尚未闭合。
- **[已否 · 教学态]**：曾是结论、已被推翻，只为交代脉络而保留。

### 5.2 论证链与排他

物理散文，过遮数检验；讲义已覆盖的推导一律 `→ 讲义 §x` 指过去，本段只写**从讲义终点到论文措辞之间的最后一跳**（口径怎么选的、为什么这样表述、边界词为什么是这几个）。

**排他收尾（机制类 claim 强制）**：本段末尾必须回答"**最强的备选解释是什么、被哪个证据排除**"。注意：排他不是防御预案，而是机制论断自身的构成部分——一个机制 claim 的成立，一半靠正面证据，一半靠排除最近的备选（实例：矩阵元增强 95% 归真实几何而非窗口采样，靠波函数级份额分解排除了"纯选择效应"这个最近的备选）。没有做过排他检验的，如实写"未做排他检验"并登记进 §3。

### 5.3 证据锚表

本 claim 落地的每个承重数字/图一行：

| 数字（论文口径） | 出处（一跳指针） | 复核状态 | 口径注记 |
|---|---|---|---|

- **口径注记**列专治"同一物理量多个数"（实例：0.811 跨-L 均值 / 0.793 L16 重算 / 0.803 published，约 1.1σ，论文引哪个、为什么）。
- **外部事实也是锚**：claim 依赖的外部前提（文献结论、训练集范围、竞品状态）同样入表，复核状态用 `已核实 / 待核`（实例："MACE 训练集不含 Bi₂Se₃"是全书最大卖点的前提，REFERENCES 自标"投稿级回查"、而 phase0 评审显示训练语料源自 MP 弛豫轨迹——该锚必须标"待核"并给核法）。`待核` 锚自动登记进 §3。
- **亲验步骤（弱 claim 强制）**：证据等级为 [已证 · 单一验证] / [待验证]、或本表含 `待核` 锚的 claim，锚表末尾必附一行亲验：一步式打开-比对操作 | 期望看到什么 | 对不上怎么办。[已证 · 独立复核] 且锚全 `已核实` 的免验。规格与深亲验 → §10；完成态汇总 → §7 接管清单。

### 5.4 薄弱点、边界与撤回条件

本 claim 最诚实的软肋，三件都要写全；承重项同步登记进 §3 总表：

- **未做检验清单**：哪些尺寸/系综/近似没测过，一条一行（实例：Redfield 相干稳健性只在 L=8、48 个 realizations 上做过，生产尺寸未验）。
- **"为什么敢不补"的完整论证**：项目当时决定不补的物理理由**原文级复述**（标度论证、对称性论证），不许用"远不到翻转所需量级"这类一句安慰替代——被追问时你要能复述的是论证，不是安慰。
- **撤回条件**：什么样的新证据/新计算一旦出现，本 claim 必须撤回、降级或改措辞。写成可判定的条件句（"若在生产尺寸复跑相干检验、修正超过 X 的量级，则符号结论需重述"）。写不出撤回条件的 claim，要么是套话（删），要么其不可证伪性本身就是重大薄弱点（记入 §3）。

### 5.5 前身与翻案

本 claim 取代过什么、旧叙事被哪个**物理证据**杀死，按时间顺序写成一段故事，句末挂 STATE 行指针。两条纪律：

- **时间线诚实**：约定 vs 发现、设计 vs 补丁，按实际发生顺序写（实例：ε∝M 的系综相关性是任务执行中才**发现**的，随后补测独立系综——不得倒叙成"设计之初即声明的约定"）。
- 主线多次换轨的项目，在第一条 claim 的本段给出全链 lineage 一句话（实例：β-drain → geometry-controls-cooling → self-limiting → conserved-coupling-redistribution），后续 claim 只写各自的一跳。

## 6. §3 薄弱点总表

**原则**：外部攻击不可穷举，但**自身的承重假设、近似、未验证锚可以穷举**——所以卷宗不预判"审稿人会问什么"，只保证"我们自己知道的每一处薄弱都在一张表上"。这张表是投稿决策的直接输入，也是深亲验的选材依据（§10）与脱稿预答复的题源（§11.2）。

**四路汇入**（各处登记的承重项自动进表）：
1. 5.4 的未做检验项（承重的）；
2. 5.3 证据锚表中所有 `待核` 外部锚；
3. §4 复核覆盖表中"无独立复核"的承重推导/代码；
4. [待验证] 态的 claim 与未闭合的验证门。

**表结构**：

| 薄弱点 | 涉及 claim | 若坐实的后果 | 处置 | 状态 |
|---|---|---|---|---|

- **若坐实的后果**三档：**毙稿级**（该假设若错，核心结论或新颖性不成立，实例：训练集若含该材料，"zero-shot"卖点作废）/ **需大修**（补计算或改结论强度）/ **措辞级**（改表述即可）。注意这一档位判断是**纯内部因果**——回答"这条假设若错，结论链在哪一环断"，不是模拟审稿人。
- **处置**四种：`补验证 / 核外部锚 / 改措辞 / 接受并写明`。最后一种是合法出口：有些薄弱点补不了，正确动作是写进论文的限制节、摆在明处，而不是藏着——**摆在明处的薄弱点是边界，藏起来的薄弱点才是炸弹**。
- **状态**：`已闭合 / 待补 / 待核 / 已写明`。
- **投稿规则（写死）**：存在"毙稿级 × 待补/待核"条目时不投稿。

## 7. §4 方法与数据可信度

**原则**：第一作者不需要会跑流水线，但必须知道对数据的信心建立在哪几道闸上、闸有没有全过、出过什么事。

**必含四件**：
- **流水线一图**：代码 → 验证门 → 数据 → 分析 → 论文数字的单张示意图（讲义配图标准同款，渲染亲验）。注意这张是**工程链**图，与 §0 的**机制链**图分工不同、不合并。
- **验证门表**：每道门一行——判据 | 当时实测值 | 过门记录指针（实例：λ 偏差 >50% 项目级弃用红线；phason D1–D3 判据全 PASS 的数值）。
- **事故簿**：数据/物料事故 + 修复方式 + **对最终数据的影响评估**（实例：ephmat 体系错配 + 悬空软链 + 损坏、全盘无完好副本 → 全量重算；影响评估：重算后数据与事故前无继承关系）。
- **复核覆盖表**：承重推导/数值代码 × 复核方式（codex-locked / user-reviewed / 同谱系自审 / **无**）一张表，"无"一列高亮置顶并登记进 §3。这张表是 5.1 标签的汇总视图，也是决定投稿前要不要补审的依据。

## 8. §5 路线史与失败分支

**原则**：§0 讲的是**结果的故事**（结论为什么成立），本节讲**寻找的故事**（我们怎么找到它）：哪些路走过、各自在哪个证据面前死掉或转向、为什么是这条路而不是那几条。这是答辩必考题（"你们试过别的吗""为什么不用 X"）的证据层，也是下一个课题选路时直接消费的历史。

**探索树一图（本节骨架）**：一张 DAG——节点是走过的路线/假设（主线换轨节点 + 无后继死支），边标注**杀死或扭转它的证据**；主线与死支画进同一张图（实例：主线 β-drain → geometry-controls-cooling → self-limiting → conserved-coupling-redistribution；死支 α/β/γ 指纹框架三轮复审后搁置、glassy E(t) PRL 钩子被双重确认证伪、存储侧重构 Stage-0 gate 未过 NO-GO）。每个节点挂一跳指针：主线前身 → 对应 claim 的 5.5 翻案段；死支 → 本节段落；检验过它的任务 → T 号。节点数由 STATE 的 decision_reversal 与路线级事件决定（真实项目通常 5–15 个），素材全部已在账；按讲义配图标准制作并渲染亲验。与 §0 机制链图是一对，**不合并**：机制链讲结果的因果，探索树讲寻找的因果。

**逐条段落（与 5.5 的分界不变）**：**现存 claim 的前身**写在该 claim 的翻案段；**没有现存后继的整条死路线**才在本节立段。每条一段，三要素：**当时的动机（物理）→ 死因（证据，带指针）→ 遗产**（留下了什么工具/数据/教训）。不写流水账，不超过一段。

**下钻路径（本节末尾写死）**：任何一个"为什么"都应能沿 `探索树节点 → TASKS §T<n> → T<n>_report → 账本` 四跳钻到原始证据。T-report 侧的回指义务（本任务检验哪个路线节点、结局是验证/证伪/搁置）是 spine 侧写入时纪律，登记在项目 CONVENTIONS——收官时考古补建的"设想与假设"是倒推的合理化，不算数；探索树负责把节点侧指针挂全，§6 的 task 覆盖扫描负责查漏。

## 9. §6 对账差异报告（机器生成）

**原则**：对账是机械劳动，由 agent 做，人只读差异。**只报异常，全绿则一行**。

**四类扫描**：
1. **数字对账**：论文稿每个数字 vs ledger 同值出处（差异定性：笔误 / 口径分歧 / 账本更新未同步）。
2. **链条完整性**：每条 claim 的 `claim → 图 → 数据文件 → 生成脚本 → 验证门记录` 五环逐环存在且可追；断环即报（实例：图存在但生成脚本丢失、验证门无过门记录）。
3. **口径矛盾**：不同文档对同一事实的记载互斥（实例：STATE 记 ~2900 词 vs 报告记 ~2650 词——定性为"合规核对未落地"，处置为"实测词数"）。
4. **task 覆盖**：ledger/reports 出现过的每个 T 号归入四类之一——支撑现存 claim（某条锚表一跳可达）/ 属于 §5 探索树某节点 / 基础设施（工具、环境、绘图类，对照 §4 流水线声明的清单）/ **孤儿**。孤儿即报差异——要么是被遗忘的教训，要么是无后继的弃子；处置建议二选一：补入探索树 / 显式登记为不入卷宗的工程杂务。

**规格**：报告头部声明扫描范围（哪份稿、哪些账本）与生成日期，并**顺带判定接管档位**（规则 → §11.1，结果写进 §1 接管状态行与 §7）；每条异常给处置建议。**触发时机**：每次投稿决策前、权威稿大改后必须重新生成；报告日期写进 §1。

## 10. 内联亲验

**原则**：第一作者责任的"亲手"部分不靠通读原始证据，也不靠单列菜单，而是**长在阅读路径上**——读到弱 claim，当场做一次不经任何 agent 中介的打开-比对。选材不再需要人挑：证据等级本身就是触发器，薄弱处自动带亲验。

**规格**：
- **触发与免验**（同 5.3）：[已证 · 单一验证] / [待验证]、或锚表含 `待核` 锚的 claim 必附亲验步骤；[已证 · 独立复核] 且锚全 `已核实` 的免验。
- **步骤三要素**：**≤10 分钟的一步式操作**（"打开某报告 §y，比对某表某行"）| **期望看到什么** | **对不上怎么办**（先查口径注记，再下钻源文件）。
- **操作级别写死**：只允许打开-比对级（读报告、看图、对表）；**不得要求跑代码、配环境或重算**——亲验检验的是"证据在不在、对不对得上"，不是复现力。
- **深亲验（黄档强制，全卷宗一项）**：纸笔复核一个最小承重推导，直接复用讲义的手算自验例，挂在 §3"承重 × 薄弱"乘积最高的那条 claim 上；绿档以讲义阅读中已做的手算自验例视为覆盖。
- **完成记录**：每项亲验在 §7 接管清单打勾；黄档亲验全勾（含深亲验）是投稿门组成部分（§11.4）。

## 11. §7 接管清单与生成性接管检验

**原则**：掌控的检验标准不是"防住提问"，也不是"读完了"，而是**生成性理解**——能脱稿把工作重新讲成一个成立的故事、能纸笔重走承重推导、能对薄弱点做扰动推演。这三件事的答案**不在任何文档里**，背不下来；能生成出来，任何方向的提问都自然接得住——防御是理解的副产品，不是训练目标。检验不设考试建制（无出题、无评分、无毕业线），折进真实工作流：**产物就是论文的一部分，检验成本即写作成本**。三项能力各有落点：讲成故事 → 脱稿产物（11.2），重走推导 → 深亲验（§10），扰动推演 → 预答复（11.2）。

### 11.1 §7 接管清单（机器生成骨架）

机械对账角色生成 §6 时顺带产出，三块：

- **亲验汇总**：从 §2 扫出全部亲验步骤（含深亲验），列成 checkbox 清单，负责人完成后打勾。
- **档位判定**（机器判，负责人不自报；[决策 / 约定] 与 [已否 · 教学态] 不计入分档）：
  - **绿档**：不含 [已证 · 单一验证] / [待验证] 承重 claim、锚全 `已核实`、§3 无"毙稿级 × 待补/待核"；
  - **黄档**：存在 [已证 · 单一验证] / [待验证] 承重 claim 或 `待核` 锚，但无"毙稿级 × 待补/待核"；
  - **红档**：存在"毙稿级 × 待补/待核"。
- **脱稿检验规格与状态**：本项目适用的产物形态、状态（未启动 / 对账中 / 已通过）、对账单指针。§1 接管状态行引用本节。

### 11.2 脱稿产出

负责人读毕卷宗、完成 §7 清单上的亲验（如有）后，**脱稿**产出一件工作流本来就需要的产物。**脱稿的定义**：产出期间不打开讲义、卷宗、账本或任何项目文档，写完才允许对照。形态三选（可组合）：

- **Introduction + Discussion 脱稿初稿**（无论文稿项目：未来论文的 Introduction 蓝本，即 §0 地图的独立重构）；
- **答辩/组会开场三分钟文字稿**；
- **§3 薄弱点总表逐条预答复**：假想每条薄弱点被问到，写下应答。这不是审稿人模拟——题源是自家穷举的薄弱点（§3），不是预判外部提问；每条就是一道"若此处失效，链条哪环先断"的扰动推演，题目是自家的，背诵无从应付。

**黄档产物必含预答复**（推荐 Introduction + 预答复组合）；绿档推荐 Introduction（反正要写），不强制。

### 11.3 机械对账与修订闭环

对账 agent（低档、非卷宗起草谱系）比对脱稿产物与卷宗/账本，**只报差异，不打分**（模板见附录 C），三类：

- **因果链偏差**：机制讲错、跳环、因果倒置；
- **证据引用偏差**：数字、口径、出处与账本不符；
- **边界遗漏**：该提的薄弱点、撤回条件、已否结论没提。

每条差异附依据与回读指针（卷宗哪节 / 讲义哪章）。负责人回读 → **修订产物**（不是重考）→ 复账；差异清零或逐条有依据处置后，检验通过。

### 11.4 落盘与投稿门（机制站岗，不靠自觉）

- 产物入正常工作流位置（paper 目录或 `reports/takeover_<日期>.md`），对账单入 `reports/`，指针记入 §7；
- STATE 追加一行：`takeover · 生成性检验通过 ref:<对账单>`；
- **投稿任务在 TASKS/DAG 中以该 takeover 事件为前置依赖**；
- **投稿门分档写死**：**红档**不投稿（即 §3 投稿规则，唯一硬门）；**黄档**：亲验全勾 + 深亲验 + 脱稿检验通过，缺一不谈投稿；**绿档**：通读卷宗即可，脱稿检验推荐不强制。

**如实声明的边界**：对账查得出偏差、查不出含糊——缓解是产物为真实论文件，含糊由下游正常评审暴露；预答复未预到而真实审稿指出的条目，按 §14 记穷举完备性失败。检验通过证明的是"能重构"，不制造"愿负责"——签字诚信仍是人的责任，超出本宪章范围；此后在真实答辩与审稿里现场重构的能力，才是掌握的最终证明。

## 12. 语言与指针纪律

- **承接讲义标准**：图像先行、遮数检验（§0 地图与 §2 论证链、翻案段逐句过）、中文纯度、符号从讲义 SYMBOLS.md 引用不另立。
- **数字纪律**：卷宗与讲义同为下游视图，**不生产数字**；但卷宗承担讲义不承担的义务——引用必带出处 + 复核状态，同一量多口径并存时**全部列出**并注明论文用哪个。
- **任务号纪律**：T 号、job 号只出现在指针位置；正文叙事的主语是物理对象和证据，不是任务。
- **指针格式**：`→ 路径 §节（或行号）`，一跳可达；交付前全量解析检查（死链实例：讲义引用不存在的 T2_report）。
- **禁语表**（出现即打回）："应该没问题"、"已充分验证"（不带复核记录）、"远不到量级"（不带论证）、"业界共识"（不带文献锚）。

## 13. 生成流程与独立性红线

### 13.1 输入全集

权威论文稿（或最新结论报告）、claims ledger、STATE 全量事件日志、ROADMAP、全部 T-reports、项目既有审读材料（如有）、讲义全书、项目 CLAUDE.md/CONVENTIONS。缺一项要在卷宗 §1 声明。

### 13.2 六角色流水线

| 角色 | 职责 | 模型档位指引 |
|---|---|---|
| claim 提取 | 从权威稿提 claim 清单，与 ledger 对齐锁定 | 中档 |
| 起草 | §0 地图 + §2/§4/§5 物理散文 | **最高档**（地图与论证链的散文质量是卷宗的命） |
| 诚实性审计 | 专猎五种失效：磨平薄弱点、洗白证据等级、倒叙时间线、撤回条件空洞化、**总表漏项**（承重假设/待核锚未入 §3）；独立重建一份薄弱点清单与起草稿的 §3 对撞，漏项即失效 | 高档，**换谱系** |
| 终审合并 | 逐条裁决起草稿与诚实性审计的冲突，规则：**以更诚实的一方为准**；产出定稿 | 高档 |
| 机械对账 | 生成 §6（四类扫描 + 档位判定）与 §7 接管清单骨架；交付后承接脱稿产物对账（§11.3） | 低档；脱稿对账换上下文 |
| 指针体检 | 全量指针解析、遮数抽检、禁语 grep | 低档 |

### 13.3 独立性红线

- 5.4（薄弱点/撤回条件）与 §3（总表）**不得由写讲义/写论文的同谱系单独产出**——执行谱系对自己的软肋天然失明、天然倾向维护原结论；诚实性审计必须换模型或换上下文。它审计的对象是**文档的诚实与完备**，不是替读者练防守。
- 终审合并不得由起草者兼任。

### 13.4 交付门

诚实性审计未过不算交付；卷宗入 git；STATE 补一行交付事件（实例教训：某项目讲义整目录未入 git、STATE 零记录，导致"讲义是否已验收"本身不可考）。

## 14. 维护

- **换轨同步义务**：任何 decision_reversal 或影响 claim 的事件，讲义与卷宗（含 §5 探索树的节点与边）**同一个 pass**内同步（实例教训：LCALCEPS 路线在讲义收口次日被判 NO-GO，反转从未同步回讲义，照读会给审稿人已被推翻的方法）。§3 总表的状态列随事件更新。
- **§6 报告**每次投稿决策前重新生成；`last_synced` 过期超过一个活跃月的卷宗，视为不可信——**过期的卷宗比没有卷宗更危险**，因为它以权威口吻说旧话。
- **真实审稿意见的用法**：应答从理解 + 卷宗现场生成（§11 的预答复是天然起点），不预写剧本；意见暴露的每条新薄弱点回填 §3 与 5.4，并与内部清单对照——**审稿人指出而总表（及预答复）里没有的条目，是穷举完备性的失败**，记入教训供下一个项目改进穷举方法。
- **收官即生成**：新项目把"讲义 + 卷宗"写进 ROADMAP/TASKS 的**收官阶段标准交付物**，在项目结束阶段由流水线生成，不留到负责人需要接管时事后补。

---

## 15. 边界情形

- **无论文稿的项目**：claim 清单改从"最新结论报告 + STATE 归纳"提取，每条标成熟度；此时卷宗是**论文的骨架而非论文的影子**——§0 物理故事地图直接充当未来论文 Introduction 的蓝本，§2 的证据锚表就是 figures 计划，先有卷宗再写稿；§6 对账对象换成"报告 vs 账本"。
- **多论文 / 多 instance 项目**：每篇论文一份卷宗，放该论文 instance 下（如 `instances/paper1/FIRST_AUTHOR_DOSSIER.md`）；项目级只留指针。
- **只有单任务教学伴读的项目**：卷宗范围仍是**全项目**，不随伴读收窄（实例：某项目唯一"讲义"只覆盖一个子方法，卷宗必须补上项目重心与全部承重结论的责任层）。
