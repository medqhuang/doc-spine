# 科研项目教学讲义编写标准

> **这份文件是什么**：一套**项目无关**的教学讲义（tutorial / onboarding 讲义）编写宪章，从本项目 `docs/tutorial/`（"无序固体中热载流子的命运"15 章讲义）的编写实践中提炼。所有具体物理（安德森局域化、守恒账本、$\alpha_0$ 等）只作**实例**出现在括注里；剥掉这些实例，剩下的条款适用于任何"长周期、多 session、可能 AI 协同"的科研项目讲义。
>
> **怎么用到新项目**：把本文件整份拷进新项目的 `docs/`，作为该项目讲义的编写宪章。动笔前通读一遍；写作时把 §10 的检验清单当 checklist；交付前跑一遍 §10 的质检关卡。文末 §11 给了可直接套用的单章模板骨架。
>
> **核心一句话**：讲义不是论文的缩写，也不是代码的注释——它是**让一个零基础的人，沿一条有依赖顺序的路径，把物理图像和承重结论真正"长"进脑子里**的东西。下面每一条标准都服务于这个目标。

---

## 0. 三条总纲（其余条款都是它们的展开）

1. **图像先行，数字作证据**——读者记住的是物理过程和因果，不是数值。先讲发生了什么、为什么；数字跟在物理论断后面当证据。
2. **单一信源，绝不造数**——讲义里每个数字都能追到唯一权威出处（论文 / 报告 / 数据账本）；不在讲义里就地算派生数字。
3. **天平偏向学生，细节一处不丢**——在"对初学者友好"和"内容完整"冲突时，优先友好；但友好靠的是**重排和下放**（移到"想深入"、脚注、后续章节），不是删内容。

---

## 1. 读者契约：先定位，再动笔

**原则**：动笔前先写死"写给谁、读者已经会什么"。读者画像决定从哪讲起、什么能跳过、什么必须现场补。

**怎么做**：
- 在 README / 总览开头**显式声明目标读者与预备知识门槛**（例：本项目讲义写"学过大二量子力学、固体物理入门、一点统计力学的本科生"）。门槛逐条列出（每条对应一门课的哪几个结论）。
- 声明**门槛不满足也能读**："相关概念用到时都会现场补讲"——并在正文兑现这句承诺，不把"预备知识"当甩锅借口。
- 明确**不需要什么**（例："不需要量子场论、重整化群的技术细节"），给读者吃定心丸。
- **从最基本的东西讲起**（"从零讲起"）。哪怕项目核心很前沿，地基章节也要从教科书级的共识概念起步，让读者站在熟悉的地面上。

**检验**：把门槛声明遮住，问"一个刚好满足门槛的人读第 1 章会不会卡？"——会卡的地方要么补讲、要么提高门槛声明。

---

## 2. 中心结论前置

**原则**：在读者被细节淹没之前，先用一段话把"全书要讲清的那个核心物理"说完。让读者带着主线读细节，而不是读完才拼出主线。

**怎么做**：
- README 顶部放一段 **"先读这一段"** 的中心结论压缩版：它同时服务两类人——第一次读的人**只扫加粗句**建立框架，读完全书的人拿它当复习提纲。
- 这段话本身要经得起"图像先行"检验：讲的是机制和因果（"无序让冷却更慢，尽管耦合在增强——机制是守恒权重的重分配"），不是结果罗列。
- 配一张**全局路线图**（见 §6），让读者能从任一基础概念追到中心结论。
- 标注**反直觉点**：如果核心结论违反朴素预期（"一个看似显然的预期是 X，本教程要讲清的恰恰是这个预期反了"），把这个张力点亮——它是读者读下去的动力。

**检验**：让一个没读过项目的人只读这一段，他能不能复述出"这项工作在问什么、答案的反直觉之处在哪"。

## 3. 单一信源：数字只有一个出处

**原则**：讲义是论文/报告/数据的**下游视图**，不是它们的并行副本。每个承重数字都指向唯一权威源；讲义自己不生产数字。

**怎么做**：
- 建立**数字账本意识**：所有出现在论断里的数值，源头是论文的 claims ledger / T-report / 数据表。讲义引用，不重算。
- **禁止 ledger 外造派生数字**：不要在讲义里把两个官方数字乘一乘、指数化一下得到第三个数（实例教训：把斜率 $0.53$ 乘以指数 $1.27$ 得 $0.67$——这个 $0.67$ 不在任何官方源里，且与真实值对不上账）。要表达关系，改写成**恒等式/合账表述**，不落地成新数字。
- 数值只施加于**论断**层；参数规格表、验证门、原始数据记录这类"账本本身"豁免（它们就是源）。
- **结论换轨时全书同步**：如果项目结论变了（叙事换轨），讲义里所有依赖旧结论的章节、图、caption 必须一次性同步改完，不留"半新半旧"的夹生态（实例：守恒-稀释账本替换已死的坍缩叙事时，14 个 md + 3 张图一次改完）。被推翻的旧结论可以保留，但必须明确标成"被否掉的猜想"教学态，不能让读者误当现结论。

**检验**：随机抽 5 个讲义里的数字，每个都要能 grep 到它在权威源里的同值出处。抽到任何一个"只在讲义里出现"的数 = 违规。

## 4. 物理图像先行（写作的第一原则）

**原则**：物理的理解方式是图像式的，不是数值式的。先讲过程、机制、因果（要有"电影感"），数字是物理论断的证据，跟在后面。

**怎么做**：

**4.1 遮数检验（每个句子都过一遍）**
把句子里的数字全遮住，剩下的文字必须**仍在陈述一个物理事实**。
- ✅ "无序把共振窗谱稀释变薄（带变宽而态总数固定），这压过了权重向幸存配对的集中"——遮住所有数字，物理还在。
- ❌ "$A$ 是 $0.53$、$B$ 是 $0.41$，所以 $A$ 压过 $B$"——遮住数字句子就空了，这是数值式写作，**重写**。

**4.2 裸数配物理锚**
任何裸数字旁边都要有物理锚，至少给一种：
- **单位/尺度**（"$W$ 以跳跃幅度 $t$ 为单位"）
- **阶段锚**（"$D_2(t)$ 这三个值各对应冷却的哪一帧"）
- **谁相对谁**（"$1.78$ 是**指数比**，不是'快 $1.78$ 倍'——幂律下'快多少倍'随时间变"）

**4.3 统计语言不替代物理陈述**
"高度显著""相关系数 $0.9$"这类统计话术不能代替物理因果的陈述。样本数 $n$ 小的时候不要引相关统计量充数。

**4.4 直觉图像 + 精确定义双轨**
每个新概念给两遍：先一个**可视化的直觉比喻**（实例："把晶格想成一排深浅不一的水坑，$t$ 是水管粗细，$\epsilon_i$ 是坑的随机深度"），再给**精确的数学定义**。比喻负责"记住"，定义负责"算对"。

**检验**：通读时把所有 `$...$` 和数字临时遮掉（或让审查 agent 这么做），逐句判断"这句话还成立吗"。空掉的句子全部重写。

## 5. 章节架构

### 5.1 阅读地图：依赖图先行

**原则**：多线索的讲义必须给出**章间依赖关系图**，让读者知道哪些章是地基、哪些可跳读、推荐路径是什么。

**怎么做**：在 README 画一张 **ASCII 依赖图（DAG）**，标出几条平行线索如何逐步汇合（实例：电子线 / 声子线 / 耦合线汇into几何-冷却桥）。配一句"按编号顺序读最稳妥"，但图的存在让有基础的人能安全跳读。再附一张**章节表**：每章一行，列"你将学到什么"。

### 5.2 单章体例（每章统一骨架）

**原则**：每章结构一致，读者形成肌肉记忆，降低导航成本。

**怎么做**：每章固定四件套（详见 §11 模板）：
- **开头 `> 这一章要解决什么`**（blockquote）：一段话讲本章打开哪个旋钮、要讲清什么、它在全书的位置。
- **正文小节**：每节"直觉图像 + 精确定义"双轨，关键物理后果用 blockquote 高亮，**陷阱显式标注**（"一个必须记住的陷阱：……"）。
- **结尾 `## 小结`**：bullet 列本章承重结论，每条能独立带走。
- **结尾 `## 想深入`**：放出处文献、下一章预告、本章文献清单（指向 REFERENCES）。

### 5.3 拆章控密度

**原则**：高潮章容易出现"密度断崖"——一节里塞进推导+审计+合龙+佐证+防误读，读者在这里掉队。

**怎么做**：监测每章/每节的概念密度。当一节承载的独立论点超过读者一次能吞下的量，**拆章**（实例：原 §11.5 单节装了"求和规则+三份额+合龙+佐证+涨落+8 条防误读"，拆成独立的第 12 章）。拆章时机械工作要做全：文件改名、章/节/图号顺延、全书交叉引用、README 流程图/章表、双向回扣链——逐项手修，sed 盲区（裸章号列表、"与 X.Y 同"这类）尤其要逐格查。

### 5.4 入口减负：不剧透、不前置术语

**原则**：读者还没学到某台"机器"时，不要在前面章节就灌它的专有术语和精确结论。入口章节给**直觉 + 指针**，完整论述只在该机器所在的章给一次。

**怎么做**：
- 引子/早期章节里，凡是要用到后面才讲的术语（实例："求和规则""谱稀释""$F_{\rm res}$"在账本机器还没教时就出现在第 1、4 章），压成直觉说法 + "（详见第 X 章）"指针。
- 完整推导只在它的主场章节出现一次，别处引用不复述。
- 早章节的长脚注、技术细节**下放**到"想深入"或后续章节——**下放不是删除**，细节一处不丢。

### 5.5 预告未来修正，不让被否结论误导读者

**原则**：如果某个漂亮结论后面会被修正/推翻，在它第一次出现的地方就**预告**，别让读者把一个"只对一半"的东西当真理记住。

**怎么做**：在结论旁加预告框（实例：第 3 章给出 $\alpha_0=1/(s+D_2/d)$ 时就注"这是定性桥不是精确律，数值检验表明它高估了敏感度，详见第 12 章"）。区分清楚**哪部分定性成立、哪部分精确不成立**，并说明"本章的地基物理不受这条修正影响"。

### 5.6 "一页表"工作总览

**原则**：给读者一张表，把"这项工作到底做了什么"压成一页。

**怎么做**：README 放一张 **问题→做法→对应章节** 的表，行可以是：问什么 / 建什么模型 / 扫哪些参数 / 测哪些量 / 发现什么 / **否掉什么** / 留下什么结论。"否掉什么"这一行很重要——明确列出被证伪的猜想，防止读者把它们当结论。

## 6. 符号纪律

**原则**：长讲义里符号撞名（同一字母在不同章指不同对象）是初学者掉队的头号杀手。符号必须有单一查询点，撞名必须显式标出。

**怎么做**：
- **全局记号约定集中一处**：单位制、抽样约定、核心变量约定（实例：自然单位 $\hbar=k_B=1$、无序抽样、质量加权、零模剔除）完整定义只在 README 给**一次**；各章第一次用到时提醒一句"（见 §全局约定）"，不重复推导。
- **建一份符号总表**（`SYMBOLS.md`）：全书符号的单一查询点，按主题分组（电子侧/声子侧/耦合侧……），每个符号给**含义 + 定义处（§章节号）**。
- **高危撞名清单置顶**：总表开头放一张撞名表，列"同一字母、不同对象"的所有情形——身份一 / 身份二 / 身份三 / **区分办法**（实例：三个 $D_2$、两个 $J$、指纹 $\gamma$ vs 衰变率 $\gamma_\nu$）。正文每个撞名点也内联提醒一句。
- 引入任何新符号时，当场交代**物理量、单位/量纲、符号约定、出处**，不让符号凭空出现。

**检验**：随机翻到中后期某章某符号，能否在 30 秒内从 SYMBOLS.md 查到它指什么、在哪定义、有没有撞名。

## 7. 配图标准

### 7.1 每章 ≥1 张图

**原则**：每章配一张承载**中心物理图像**的图。物理是图像式的，没图的章节读者抓不住主线。

**怎么做**：盘点全书，确保每章至少一张图。补图时新作教学示意图覆盖所有无图章节。

### 7.2 三类图来源，caption 标清类型

**原则**：图分三类，来源和版权边界不同，caption 必须标明，不让读者把示意图当数据。

**怎么做**：
- **教学示意图**：自制，放 `assets/`，用来解释概念关系。caption 标 **"（教学示意图）"**，并写明它示意的物理，注明"不代表真实数据"。
- **本项目真实结果图**：优先引用由项目数据生成的图（来自论文 figures 目录）。caption 标 **"（真实结果图）"** + 来源任务/脚本。
- **外部论文/教材图**：**默认不直接嵌**。只在许可明确时才嵌；否则**重画教学版** + 正文句末引用原文献（既避版权，也避原图语境错位）。

### 7.3 教学示意图必须渲染亲验

**原则**：图必须真的能正确渲染，不能写完 SVG/代码就当它对了。

**怎么做**：每张自制图（SVG 等）生成后**实际渲染检查**一遍（实例：headless-Chrome 渲染亲验）。引用真实结果图时，对着 PNG 亲验后再写 caption，确保描述与图一致。

### 7.4 "读图法" caption

**原则**：真实结果图对初学者是天书。caption 不只说"这是什么图"，还要**教读者怎么读**——看哪条线、哪个对比、说明什么物理。

**怎么做**：每张承重的真实结果图，caption 里加一段"读图法"：眼睛先落在哪、对比的是什么、得出的物理结论是什么（实例："看守恒平坦 + $\Sigma_\delta$ 对比 / 两条斜率 + 净速率降 30%"）。

**检验**：让没读正文的人只看图 + caption，能不能说出这张图在讲什么物理。

## 8. 自学化：讲义而非习题集

**原则**：目标是一份能**独立自学**的讲义。知识全部写进正文，不依赖"做完习题才懂"。

**怎么做**：
- **不留悬空习题**。如果某个"想一想"承载了必要知识，把那个知识**织进正文**讲明白，而不是留给读者自己悟（实例：撤掉全部"想一想"，其承载的 ~14 处知识点融入正文）。
- **手算自验例**：关键公式给一个**最小可手算的例子**，让读者用纸笔验证一遍（实例：2 格点 × 2 态 × 2 模手算求和规则，验证 $S_1=g^2+h^2$ 与角度 $\theta$ 无关）。例子要**自验**——结果能当场对上，读者获得"我真的懂了"的确认。
- 把"工作怎么真正做出来"的细节也写全（参数权威表、一次完整计算的流水线），让讲义能**接上真实项目文档**，而不是停在原理层。

---

## 9. 引用与文献

**原则**：文献既是出处也是延伸阅读地图。引用方式统一，书目带注解。

**怎么做**：
- **句末挂标**：正文用 `[作者 年份]` 在句末标注，不打断阅读流。
- **注解书目**（REFERENCES）：每篇文献给**完整出处 + 一句话"讲什么" + 在本讲义里的角色**，不是裸 bibTeX。让读者知道为什么要读它、读它解决什么。
- 章末"想深入"列**本章文献清单**，指向 REFERENCES 的注解条目。
- 文献表与正文引用**双向同步**：正文引了的都在表里，表里删了的正文也清掉（别留"某文献不再被引用"的过期注脚）。

---

## 10. 语言纯度

**原则**：中文讲义就全中文，术语黑话不留英文散词。

**怎么做**：正文不夹未翻译的英文术语/黑话（实例：清掉 "distinctiveness" 这类漏网词）。专有名词首次出现给中文译名 + 括注英文原词，之后用中文。交付前做一遍**全量词表普查**（grep 英文散词）。代码、命令、标准缩写（IPR、DAG 等约定俗成的）保持原样。

---

## 11. 质检关卡（交付前必过）

**原则**：讲义交付前过一遍多维度独立审查，单一作者视角看不出自己的盲点。

**怎么做**：

**11.1 多维独立审查**
用若干**独立审查 agent**分片只读审全书，每个 agent 一个视角，至少覆盖这些维度：
- **正确性**：数字 vs 权威账本是否一致、有没有派生数字、逻辑有没有断层
- **死叙事残留**：被推翻的旧结论有没有以"现结论"姿态残留（被否的必须标成教学态）
- **教学性**：首读者体验、认知负荷与概念依赖顺序、配图与例子的教学力
- **图与引用**：图是否都存在且编号正确、文献是否完备、引用是否双向闭合
- **红线**：项目特定的措辞红线有没有违反

**11.2 grep 电池**（机械自查，审查前先跑）
- 悬空节号/图号、嵌入图路径能否解析、旧名残留、README 链接有效性、英文散词、章号交叉引用一致性。

**11.3 数值/派生类强制独立 review**

**11.4 交付物双满足**
对照任务的 Output 清单（要产出哪些文件）和 Criteria 清单（要满足哪些标准）**逐项 cross-check**，两者都满足才算交付。Output 视觉权重弱、容易漏，要专门 grep 一遍。
